#+title: Mode Command Refactor Plan

* Problem
Mode commands (defined via =defmode-command=) are registered in the global
command tables as soon as a mode's Lisp file is loaded, and merely "disabled"
at call time when the owning mode is inactive. This:
1. Pollutes the command space (help, completion, ACP, TUI) with inactive
   commands.
2. Prevents two modes from exposing the same command name (e.g. =route.create=
   for both a Rails mode and a React-Router mode), because both register at load
   time and collide.

* Goal
- A mode's commands are *defined* (registered) only when the mode is *activated*.
- A mode's commands are *undefined* (removed) when the mode is *deactivated*.
- Different modes may declare commands with the same bare name; the active
  mode's implementation is the live one.

* Design
** mode struct (mode.lisp)
Add two slots:
- =command-definers= :: alist of (command-name . thunk). Each thunk defines the
  command via =define-command=.
- =active-command-names= :: command names currently registered by this mode,
  used to undefine them on deactivation.

** defmode-command (mode.lisp)
Expands to =register-mode-command= with the *bare* command name and a thunk that
performs the =define-command=. No mode prefix, so modes can share names.

** register-mode-command (mode.lisp)
Attaches a definer to a mode. If the mode is already active, defines the command
immediately.

** activate-mode (mode.lisp)
Runs each command definer and records the bare names.

** deactivate-mode (mode.lisp)
For each command the mode registered: if another *active* mode also provides
that name, re-run that mode's definer (restore it); otherwise =undefine-command=.

** undefine-command (commands.lisp)
Removes a command from =*commands*=, =*sub-commands*=, =*command-completions*=,
=*acp-commands*=, and the hidden / tui-hidden / editor-hidden sets.

** defmode reload safety (mode.lisp)
If a mode is redefined while active, deactivate it first so stale commands are
removed before the fresh definition is installed.

* Conflict handling
When several active modes declare the same command name the most recently
activated mode wins; deactivating it restores the next active provider, if any.

* Tests (tests/mode.test.lisp)
- A mode command is absent before activation, present/runnable after activation,
  and absent again after deactivation.
- Two modes declaring the same command name coexist; activation selects the live
  implementation and deactivation restores/removes correctly.

* Touched files
- mode.lisp, commands.lisp, react-mode.lisp, modes/rails.lisp, tests/mode.test.lisp

* North Star

Hactar is not a tool you point at a project. *Hactar becomes the project.*

On first run inside a repository, the generic engine detects the project,
extracts a map of its stack and shape, and writes a project-local application to
=.hactar.lisp=. From that point forward, running =hactar= means running the
project's own generated and editable CLI. The global engine recedes into a
library.

The rebuild should treat the current codebase as reference material only and all existing code must be removed at the end of the rebuild process. This is a complete rebuild from scratch. The target is a clean implementation whose central product is the generated harness:
=.hactar.lisp=, a human-readable DSL program that composes project tools, skills,
prompts, actions, sandboxes, and agents.

#+begin_quote
Hactar is a DSL for building dev tooling from LLMs. =.hactar.lisp= is a program
written in that DSL, and Hactar writes most of it for you, then keeps writing it.
#+end_quote

* Product Invariants

1. Hactar solves repeatable problems by extending itself, not by emitting
   throwaway bash or Python scripts.
2. The generated =.hactar.lisp= is the application for one repository.
3. The engine defines no project-specific verbs beyond bootstrap, build, doctor,
   and update machinery.
4. Project behavior lives in readable DSL forms.
5. User-written regions are preserved; generated regions are machine-owned.
6. Self-update is enabled by default but is always validated before reload.
7. All mutable engine state is declared from one file, =state.lisp=.
8. Build, test, run, and development entry points go through the Makefile.
9. The project-local binary always lands at =./hactar/build/hactar=.
10. A generated =.envrc= and launcher shim make =hactar= resolve to the
    project-local binary when inside that repository.
11. Agents edit code through AST operations, not text matching. String-based
    edits are a fallback for languages without AST support.
12. All tools are defined as Lisp function bodies. Agents call universal Lisp
    tools (e.g. `(test)` or `(lint)`) rather than running raw shell commands.
    Under the hood, these tools use stack-sensitive functions to run the
    correct toolchain commands.

* Architecture

** Layer 1: =hactar-core=

=hactar-core= is the reusable engine library. It owns the kernel, DSL registry,
core commands, bootstrapper, self-generation pipeline, self-update pipeline,
dispatcher, builder, validation, persistence, and interfaces.

It should provide only these generic commands:

- =hactar.init= / first-run bootstrap
- =hactar.build=
- =hactar.doctor=
- =hactar.update=
- =hactar.version=
- =hactar.help=

Every stack-specific verb is generated into =.hactar.lisp=.

** Layer 2: =.hactar.lisp=

=.hactar.lisp= is the per-project application. Loading it registers the project
model and its commands. It is both user editable and machine editable.

Canonical shape:

#+begin_src lisp
  (in-package :hactar-user)

  (generated :updated-at "<timestamp>"
    (defproject :stack ("typescript" "react" "react-router" "vite"))

    ;; Universal project tools defined as simple Lisp functions
    (deftool test (&optional file)
      "Run unit tests. Resolves to the correct toolchain automatically."
      (run-test-cmd file))

    (deftool lint ()
      "Lint the project."
      (run-lint-cmd))

    ;; Stack-specific tool
    (deftool rr-routes ()
      "List the route tree."
      (shell-cmd "npx react-router routes"))

    ;; AST-first editing tool
    (deftool ast-edit (path &rest ops)
      "Structural edits by symbol kind and name."
      (run-ast-edit path ops))

    (defskill react-router :doc "react-router.org" :rules :react-router)

    (defsandbox project :allow ("npx" "node" "git"))

    (defaction route.create
      :doc "Create a typed React Router route + loader/action."
      :prompt "Create a React Router route {{name}} under src/routes using a typed loader and action, then register it in src/routes.tsx. {{doc:react-router}}"
      :apply :create)

    (defagent dev
      :model "anthropic/claude-sonnet-4-6"
      :tools (test lint rr-routes ast-edit)
      :skills (react-router)
      :sandbox project
      :instructions "Build React Router features end-to-end. Use (test)
                     to verify. Edit TypeScript through ast-edit when possible."))

  ;; User-owned forms below this line are preserved across updates.
#+end_src

** Binary, Loading, and Rebuild Model

This is the most important implementation decision and must be settled before
Phase 6. The engine ships as a single precompiled binary (via Roswell, Nix, or a
release tarball). A project does not require the user to have a Lisp toolchain.

Resolve the apparent tension between "build binary" and "ship a binary" as
follows:

- =.hactar.lisp= is *data plus DSL forms loaded at runtime*, not statically
  linked into a binary. The project-local =./hactar/build/hactar= is, by default,
  the engine binary (or a thin shim to it) that loads =.hactar.lisp= from the
  repository root on startup.
- "Build binary" in bootstrap means: ensure =./hactar/build/hactar= exists and
  points at a runnable Hactar. On a toolchain-equipped machine this may be an
  ahead-of-time =asdf:make= image that bakes in =.hactar.lisp= for fast startup;
  on a binary-only install it is a copy or symlink of the engine binary that
  loads =.hactar.lisp= at runtime. Both paths must produce identical dispatch
  behavior.
- *Hot-reload* re-reads and re-evaluates =.hactar.lisp= into the running image.
  It is sufficient for registry-level forms: =deftool=, =defskill=, =defsandbox=,
  =defagent=, =defaction=, =defprompt=, =defrule=, =defdoc=, =defroute=,
  =defmode=, =defhook=, and the project map forms. The vast majority of
  self-update edits are registry-level and never require a rebuild.
- *Rebuild* (re-running =asdf:make=) is only needed when a form changes something
  the image cannot patch at runtime — new package definitions, new macros, or
  changes to the engine itself. The self-update agent must classify each diff and
  choose reload vs rebuild; when unsure, reload and defer rebuild to an explicit
  =hactar.build=.
- Whether AOT-baked or runtime-loaded, a missing or stale binary is repaired by
  =hactar.doctor=.

* Packaging and Symbol Strategy

=.hactar.lisp= begins with =(in-package :hactar-user)=. The =hactar-user= package
is created by =hactar-core= and =:use=-s the closed DSL surface so that every
emittable form (=defproject=, =deftool=, =defskill=, =defsandbox=, =defagent=,
=defaction=, =defprompt=, =defrule=, =defdoc=, =defhypertext=, =defroute=,
=defmode=, =defcommand=, =defhook=, =definterface=, and =generated=) resolves
without package prefixes. This keeps the generated file readable and keeps the
human and the diffusion agent writing the same vocabulary.

Rules:

- =hactar-core= exports exactly the DSL surface (and nothing else) into a package
  designed for =:use= by =hactar-user=.
- =hactar-user= is reset (its registries cleared, and ideally the package
  recreated) before each load of =.hactar.lisp= so reloads are idempotent and
  stale definitions do not linger.
- The validator runs against the textual forms *before* they are read into
  =hactar-user=, so a malformed or out-of-surface form never reaches the
  evaluator in a privileged package.
- Load =.hactar.lisp= with =*read-eval*= bound to =nil= so untrusted regions
  cannot execute reader-time code.

* DSL Surface

The DSL is the closed API that humans write and the self-update agent is allowed
to emit. Every form must validate before it can be loaded.

** =defproject=

Declares the project identity and stack. Exactly one per =.hactar.lisp=.

#+begin_src lisp
(defproject :name "my-app"
  :stack ("typescript" "react" "react-router" "vite")
  :root "/home/user/my-app")
#+end_src

** =defsandbox=

Execution policy for tools and shell commands. Restricts which binaries a tool

#+begin_src lisp

  :deny ("rm -rf /")

Emacs-inspired hooks.

#+end_src

** =defaction=

Project verbs. An action binds prompt, tools, skills, and an apply strategy.

#+begin_src lisp
(defaction route.create
  :doc "Create a typed route."
  :prompt create-route
  :tools (tsc vitest)
  :skills (react-router)
  :apply :create)
#+end_src

** =deftool=

Defines a tool as a Lisp function with a docstring and a body of forms. Tool bodies can execute shell commands via =(shell-cmd "...")=, execute other agents via a =(with-agent ...)= block, or run stack-sensitive functions.

#+begin_src lisp
;; Simple shell-wrapping tool
(deftool tsc (&optional args)
  "Run the TypeScript compiler."
  (shell-cmd (format nil "npx tsc --noEmit ~A" args)))

;; Universal tool using stack-sensitive dispatch
(deftool test (&optional file)
  "Run unit tests for the current stack."
  (run-test-cmd file))

;; Tool utilizing an agent for structural changes
(deftool refactor (file symbol)
  "Refactor a symbol across the codebase."
  (with-agent (:model "anthropic/claude-sonnet-4-6")
    (agent-run (format nil "Refactor symbol ~A in ~A" symbol file))))
#+end_src

** =defroute=

Transforms command strings into normalized route data. =defroute= owns parsing
(=--flag=value= into named parameters) and *normalization* (coercing parameter
values into canonical form before dispatch).

#+begin_src lisp
(defroute routes.create
  :pattern "/routes.create --name={name} --path={path}"
  :coerce  ((:path ensure-leading-slash))
  :result  (:cmd "routes.route" :name name :path path))
#+end_src

Required example:

#+begin_src text
/routes.create --name=login --path=login
#+end_src

normalizes to:

#+begin_src lisp
(:cmd "routes.route"
 :name "login"
 :path "/login")
#+end_src

Note the transform: =--path=login= becomes =:path "/login"=. The leading slash is
added by the =:coerce= rule, not by the caller. =defroute= must make such
normalizations explicit and testable rather than implicit in handler code.

** =defhypertext= and =defdoc=

=defhypertext= is the underlying document graph. =defdoc= is the friendly DSL
layer on top.

#+begin_src lisp
(defhypertext react-router-docs
  :uri "react-router.org"
  :content "...indexed docs...")

(defdoc react-router
  :uri "react-router.org"
  :tags (:react :routing))
#+end_src

** =generated=

The machine-owned region wrapper.

#+begin_src lisp
(generated :updated-at "<2026-06-30 Tue 14:15>"
  ...)
#+end_src

Rules:

- The self-update agent may replace any form inside =generated=.
- User forms outside =generated= are preserved.
- The validator rejects forms outside the closed DSL surface unless they are in a
  user-owned region and explicitly loaded under a trusted package.
- The writer preserves comments and reasonable formatting where possible.

* Editing Model: AST-First

Inspired by SoulForge's =ast_edit= tool, Hactar's core editing primitive is
AST-based. Agents address code by symbol kind and name, mutate structurally, and
write back. Micro-edits cost a handful of tokens and never fail on whitespace.
String-based =edit_file= is a fallback for languages without AST support.

** Principles

1. *Edit by symbol, not string.* The agent specifies a target (=function=,
   =class=, =method=, =variable=, etc.) and a name. The engine finds it in the
   AST and applies the operation. No line numbers, no regex, no whitespace
   fragility.
2. *Tiered operations.* Operations are classified by token cost:
   - Tier 1 (micro-edits, 1–10 tokens): rename, set type, toggle modifiers,
     add/remove parameters.
   - Tier 2 (body surgery, 10–100 tokens): replace function body, add methods,
     set extends/implements, add properties.
   - Tier 3 (full replacement): replace an entire symbol declaration.
   - File-level: add/remove imports, add top-level declarations, organize
     imports.
3. *Atomic batches.* Multiple operations can be submitted as a batch. If any
   fails, none are applied.
4. *Stack-specific AST backends.* The default AST backend is =fern= (see
   =fern.lisp=), Hactar's native Common Lisp tree-sitter-style engine. Fern
   provides PEG grammars (=defgrammar=), full and incremental parsing
   (=fern-parse=, =fern-edit=), tree-sitter-style queries (=fern-query=,
   =fern-query-nodes=), and byte/point-addressed =fern-node= trees. Each
   language/stack mode selects or extends a Fern grammar rather than shelling
   out to an external toolchain:
   - TypeScript/JavaScript/TSX: the built-in =fern= =:typescript= / =:tsx=
     grammars (no =ts-morph=/=node= dependency required). External backends
     like =ts-morph= are an optional fallback only.
   - Common Lisp: sexp-based structural editing (Hactar eats its own food);
     may also be expressed as a Fern grammar.
   - Other languages: add a Fern grammar via =defgrammar=; regex/string edit is
     the last-resort fallback where no grammar exists.
5. *Pre/post diagnostics.* After every edit, the engine captures diagnostics
   (type errors, lint warnings) and feeds them back to the agent immediately,
   without requiring a full typecheck run.

** DSL Integration

AST editing is exposed to agents as a tool defined using Lisp. Under the hood
=run-ast-edit= resolves the file's language to a =fern= grammar, parses with
=fern-parse=, locates the target node via =fern-query=, applies the structural
operation, and writes back (using =fern-edit= for incremental reparsing):

#+begin_src lisp
(deftool ast-edit (path &rest operations)
  "Structural edits by symbol kind and name."
  (run-ast-edit path operations))
#+end_src

The agent calls it with structured operations, not shell commands:

#+begin_src lisp
;; Agent tool call: set a function's return type
(ast-edit "src/api.ts"
  :action :set-return-type
  :target :function
  :name "fetchUser"
  :value "Promise<User>")

;; Agent tool call: batch operations (all-or-nothing)
(ast-edit "src/api.ts"
  :operations
  ((:action :set-async :target :function :name "fetchUser" :value t)
   (:action :add-parameter :target :function :name "fetchUser"
    :value "cache: boolean")
   (:action :add-named-import :value "./types" :new-code "User")))

;; Agent tool call: replace a function body
(ast-edit "src/util.ts"
  :action :set-body
  :target :function
  :name "parseInput"
  :new-code "return JSON.parse(raw);")
#+end_src

** Targets

| Target | Addressed by |
|---+---|
| =function=, =class=, =interface=, =type=, =enum=, =variable=, =constant= | name |
| =method=, =property= | ="ClassName.member"= or ="member"= |
| =arrow-function= | name (targets =const fn = () => {}=) |
| =constructor= | ClassName |

** Action Tiers

*** Tier 1: Micro-edits (1–10 tokens)

=set-type=, =set-return-type=, =set-initializer=, =remove-initializer=,
=set-value=, =set-async=, =set-generator=, =set-export=, =set-default-export=,
=set-abstract=, =set-static=, =set-readonly=, =set-scope=, =set-optional=,
=rename=, =remove=, =add-parameter=, =remove-parameter=.

*** Tier 2: Body surgery (10–100 tokens)

=set-body=, =add-statement=, =insert-statement=, =remove-statement=,
=add-property=, =remove-property=, =add-method=, =remove-method=,
=add-constructor=, =set-extends=, =add-extends=, =remove-extends=,
=add-implements=, =remove-implements=, =add-type-parameter=, =add-decorator=,
=remove-decorator=, =add-jsdoc=, =remove-jsdoc=, =unwrap=, =set-structure=,
=extract-interface=.

*** Tier 3: Full replacement

=replace=, =replace-in-body=.

*** File-level

=create-file=, =add-import=, =remove-import=, =add-named-import=,
=remove-named-import=, =set-module-specifier=, =organize-imports=,
=fix-missing-imports=, =fix-unused=, =add-function=, =add-class=,
=add-interface=, =add-type-alias=, =add-enum=, =add-variable=, =insert-text=.

** Safety

- File snapshotted before the edit; rejects if changed on disk mid-flight.
- Atomic batches: all or none.
- Undo reverses =ast-edit= the same as any other edit.
- Pre/post diagnostics: new type errors flow back to the agent immediately.
- Structural correctness is guaranteed by the =fern= parser: an edit that would
  not reparse cleanly under the file's Fern grammar is rejected before write.

** Fern AST backend

=fern.lisp= is the reusable AST engine that all structural editing builds on.
It should be treated as the home for AST/parse logic (eventually extracted into
its own system, e.g. =hactar-fern=, alongside the other split libraries).

Key surface used by =run-ast-edit= and the stack modes:

- =defgrammar= — declare/extend a PEG grammar (built-ins: =:typescript=, =:tsx=).
- =fern-parse= — parse source into a =fern-tree= of =fern-node= records.
- =fern-edit= — apply an incremental =fern-edit= for fast reparsing after a write.
- =fern-query= / =fern-query-nodes= — tree-sitter-style node queries used to
  locate edit targets (=function=, =class=, =method=, etc.) by kind and name.

New language support is added by writing a Fern grammar, not by adding an
external toolchain dependency.

* Universal Project Tools

Hactar provides universal tools defined as simple Lisp functions (e.g. =test=, =lint=, =typecheck=, =build=) that invoke stack-specific commands. The agent calls =(test)= or =(test "src/foo.test.ts")= instead of raw shell commands like =npm test= or =cargo test=.

** Why

Without universal tools, the agent burns steps guessing:

#+begin_src text
Agent: I'll run the tests with `npm test`
Shell: npm ERR! missing script: test
Agent: Let me try `npx jest`...
#+end_src

With =(test)=, one call detects the toolchain and runs the correct command.

** How It Works

1. During bootstrap, stack detection (=src/modes/detect.lisp=) identifies the linter, test runner, typechecker, etc.
2. Stack modes provide implementations for functions like `run-test-cmd` or `run-lint-cmd` which are called by the universal tools.
3. When the agent calls =(test)=, the Lisp function executes the resolved stack-specific command via the sandboxed =(shell-cmd)=.

** Supported Ecosystems

Toolchain detection scans config files and lockfiles:

| Config file | Ecosystem | Test | Lint | Typecheck | Build |
|---+---+---+---+---+---|
| =package.json= + =bun.lock= | Bun | =bun test= | biome/eslint | =tsc= | =bun run build= |
| =package.json= | Node | =npm test= | biome/eslint | =tsc= | =npm run build= |
| =Cargo.toml= | Rust | =cargo test= | =cargo clippy= | =cargo check= | =cargo build= |
| =go.mod= | Go | =go test= | =golangci-lint= | =go build= | =go build= |
| =pyproject.toml= | Python | =pytest= | =ruff= | =pyright=/=mypy= | — |
| =Gemfile= | Ruby | =rspec= | =rubocop= | — | — |
| =*.asd= | Common Lisp | =make test= | — | — | =make build= |

Stack modes extend this table. Each mode's detect function populates the action
mapping.

* Core Data Model

All mutable =hactar-core= state is declared in =src/state.lisp= using a single
state declaration macro (the =defstate= pattern: like =defvar= but registered for
introspection, reset, and the =/state= command). Other =hactar-core= files may
read or mutate state, but may not introduce new global mutable variables
directly.

Scope of the rule:

- The single-file rule applies to =hactar-core=. Each split library
  (=hactar-llm=, =hactar-org=, =hactar-md=, =hactar-fzf=) owns its own internal
  state and must not declare globals into =hactar-core='s =state.lisp=.
- Cross-cutting state that =hactar-core= needs from a library (e.g. the current
  model) is mirrored or referenced through a core =defstate= variable, so the
  =/state= surface stays complete.
- Every =defstate= variable should carry a doc string and, where meaningful, a
  type and examples, so state is self-describing for the editor/org interfaces.

- process and CLI state
- repository metadata
- project map
- command registry
- route registry

* Bootstrap Pipeline

** Detect

Given a repository root:

1. Identify language and package managers.
2. Identify frameworks.
3. Identify test, lint, typecheck, and build commands.
4. Identify routing/data/model conventions.
5. Produce a normalized stack descriptor.

** Extract

Build a compact project map:

- files of interest
- routes
- models/schemas
- scripts
- dependencies
- docs
- conventions inferred from tests/config
- likely commands

** Generate

Generate a complete =.hactar.lisp=:

1. =defproject=
2. project map forms
3. generated tools
4. generated skills
5. generated sandbox
6. generated prompts
7. generated stack-specific actions
8. generated =defagent= harness

Generation should prefer deterministic rules first, then LLM/diffusion for the
project-specific harness text.

** Validate

Before writing or loading:

- Parse all forms.
- Check every generated form against the DSL surface.
- Ensure referenced tools/skills/sandboxes exist.
- Ensure action and agent names resolve through the dispatcher.
- Ensure generated commands do not shadow core commands unless explicitly
  marked as overrides.

** Write

Create =.hactar.lisp= with one =generated= form plus an empty user region.

** Build

Run the Makefile build target. The resulting binary must be:

#+begin_src text
./hactar/build/hactar
#+end_src

** Wire

Create or patch =.envrc=:

#+begin_src sh
PATH_add hactar/build
watch_file .hactar.lisp
#+end_src

Install a global shim that delegates to the nearest project-local
=hactar/build/hactar= when present, otherwise falls back to the generic engine.

* Runtime Dispatch

Startup algorithm:

1. Find repository root.
2. If no =.hactar.lisp= exists, bootstrap.
3. Load =.hactar.lisp= into =hactar-user=.
4. Register generated and user-defined commands.
5. Parse CLI input through =defroute= routes and the command dispatcher.
6. Run actions, tools, or agents.
7. Record chat, tool calls, command results, validations, and file changes.
8. Trigger self-update hooks unless disabled.

* Self-Update Pipeline

Self-update is implemented as hooks around turns and tool calls.

Primary hook:

#+begin_src lisp
(defhook turn.after
  :args (turn activity)
  :doc "Update the project harness after each completed turn.")
#+end_src

Default behavior:

1. Collect recent chat messages, tool calls, command outcomes, file edits, build
   failures, and successful fixes.
2. Summarize them into a self-update ledger.
3. Ask the diffusion model for edits to the generated region.
4. Allow the diffusion model to emit any DSL-valid Lisp code.
5. Parse and validate the result.
6. Merge with the current generated region.
7. Write =.hactar.lisp= atomically.
8. Hot-reload if only registry-level forms changed.
9. Rebuild if macros/package/build-affecting forms changed.
10. Roll back on parse, validation, load, or build failure.

The self-update agent is not allowed to silently ignore validation failures. It
must record the failure in state and expose it through =hactar.update.status=.

** Diffusion Model

"Diffusion" here means a fast, low-latency edit model that rewrites the generated
region as a whole rather than a slow chat completion that emits a diff
token-by-token. The contract:

- Input: the current generated region plus a compact activity ledger.
- Output: a complete replacement generated region (DSL forms only).
- The engine never trusts the output blindly; it always parses, validates against
  the closed surface, and diffs before applying.
- The diffusion client lives in =hactar-llm= alongside =complete= and =ask=, but
  may target a different (cheaper/faster) model than the project's =defagent=
  model. It is configurable via =HACTAR_DIFFUSION_MODEL=.
- A deterministic, network-free mock diffusion client must exist for tests so the
  self-update pipeline can be exercised without API access.

** Cadence and Performance

Running diffuse + validate + reload on literally every turn can be slow and
costly. The pipeline must therefore:

- Debounce: coalesce rapid activity and run at most one update per quiescent
  window (configurable; default a few seconds after the last event).
- Run off the critical path: perform diffusion asynchronously so it never blocks
  the user's command from returning.
- Skip no-op updates: if the ledger has not changed materially since the last
  successful update, do nothing.
- Be cancellable: a newer turn supersedes an in-flight update.
- Respect =--auto-update=off= and an explicit =hactar.update= manual trigger.

;;; src/dsl/defhook.lisp
(in-package :hactar)

(defstruct hook name args doc (handlers '()))

(defmacro defhook (name &key args doc)
  "Declare a named hook. Handlers are attached later with ADD-HANDLER."
  (let ((key (string-downcase (symbol-name name))))
    `(setf (gethash ,key *hooks*)
           (make-hook :name ',name :args ',args :doc ,doc))))

(defun add-handler (hook-name fn)
  (let* ((key (string-downcase (symbol-name hook-name)))
         (hook (gethash key *hooks*)))
    (unless hook (error "Unknown hook ~A" hook-name))
    ;; newest first, like nhooks
    (push fn (hook-handlers hook))))

(defun run-hook (hook-name &rest args)
  "Run all handlers; collect their results. Errors are isolated per-handler."
  (let ((hook (gethash (string-downcase (symbol-name hook-name)) *hooks*)))
    (when hook
      (loop for fn in (hook-handlers hook)
            collect (handler-case (apply fn args)
                      (error (e)
                        (warn "hook ~A handler failed: ~A" hook-name e)
                        nil))))))

(defhook turn.after :args (turn activity)
  :doc "Runs after a completed user/agent turn.")

** =deftool= and the sandboxed runner

#+begin_src lisp
;;; src/dsl/deftool.lisp
(in-package :hactar)

(defstruct tool-def name doc fn)

(defmacro deftool (name lambda-list &body body)
  "Register a tool as a function. The body contains the Lisp forms to execute."
  (let ((key (string-downcase (symbol-name name)))
        (doc (if (stringp (first body)) (first body) "No documentation."))
        (forms (if (stringp (first body)) (rest body) body)))
    `(progn
       (defun ,name ,lambda-list
         ,@forms)
       (setf (gethash ,key *tools*)
             (make-tool-def :name ,key :doc ,doc :fn (function ,name))))))

(defun run-tool (name args)
  "Run a registered tool by applying ARGS to its function. Returns a RESULT."
  (let ((tool (gethash (string-downcase (string name)) *tools*)))
    (unless tool
      (return-from run-tool
        (make-result :status :error :message (format nil "No such tool: ~A" name))))
    (handler-case
        (let ((val (apply (tool-def-fn tool) args)))
          (if (typep val 'result)
              val
              (make-result :status :ok :message (format nil "~S" val))))
      (error (e)
        (make-result :status :error :message (princ-to-string e))))))

(defun shell-cmd (cmd &key sandbox)
  "Execute shell command under sandbox policy."
  (sandbox-check sandbox cmd)
  (multiple-value-bind (out err code)
      (uiop:run-program cmd :output :string :error-output :string
                            :ignore-error-status t)
    (make-result :status (if (zerop code) :ok :error)
                 :message (if (zerop code) out err)
                 :data (list :exit-code code :stdout out :stderr err))))
#+end_src

** =defsandbox= and policy enforcement

#+begin_src lisp
;;; src/dsl/defsandbox.lisp
(in-package :hactar)

(defstruct sandbox-def name kind (allow '()) (deny '()) cwd)

(defmacro defsandbox (name &key (kind :local) allow deny cwd)
  (let ((key (string-downcase (symbol-name name))))
    `(setf (gethash ,key *sandboxes*)
           (make-sandbox-def :name ,key :kind ,kind
                             :allow ',allow :deny ',deny :cwd ,cwd))))

(defun sandbox-check (sandbox-name cmd)
  "Signal an error if CMD violates the named sandbox's allow/deny lists."
  (when sandbox-name
    (let* ((sb (gethash (string-downcase (string sandbox-name)) *sandboxes*))
           (bin (first (str:split " " (str:trim cmd)))))
      (when sb
        (when (find-if (lambda (d) (search d cmd)) (sandbox-def-deny sb))
          (error "Sandbox ~A denies: ~A" sandbox-name cmd))
        (when (and (sandbox-def-allow sb)
                   (not (member bin (sandbox-def-allow sb) :test #'string=)))
          (error "Sandbox ~A does not allow binary: ~A" sandbox-name bin))))))
#+end_src

** =defprompt= and template rendering

Use mustache-style =\{\{var\}\}= plus =\{\{doc:NAME\}\}= and =\{\{stack\}\}=
expansions, matching the worked example.

#+begin_src lisp
;;; src/dsl/defprompt.lisp
(in-package :hactar)

(defstruct prompt-def name args template)

(defmacro defprompt (name args template)
  (let ((key (string-downcase (symbol-name name))))
    `(setf (gethash ,key *prompts*)
           (make-prompt-def :name ,key :args ',args :template ,template))))

(defun render-prompt (prompt params)
  "PROMPT is a prompt name (symbol) or a literal template string."
  (let ((tmpl (if (and (symbolp prompt) (gethash (string-downcase (string prompt)) *prompts*))
                  (prompt-def-template (gethash (string-downcase (string prompt)) *prompts*))
                  (princ-to-string prompt))))
    (labels ((expand (s)
               ;; {{stack}} -> space-joined stack
               (setf s (cl-ppcre:regex-replace-all "\\{\\{stack\\}\\}" s
                        (format nil "~{~A~^ ~}" *stack*)))
               ;; {{doc:NAME}} -> doc body
               (setf s (cl-ppcre:regex-replace-all "\\{\\{doc:([^}]+)\\}\\}" s
                        (lambda (m &rest _) (declare (ignore _)) (lookup-doc m))))
               ;; {{name}} etc. from PARAMS plist
               (loop for (k v) on params by #'cddr
                     do (setf s (cl-ppcre:regex-replace-all
                                 (format nil "\\{\\{~A\\}\\}" (string-downcase (string k)))
                                 s (princ-to-string v))))
               s))
      (expand tmpl))))

** =generated=, reading, writing, and region preservation

=generated= is dual-natured: at *load time* it is a macro that simply evaluates
its body; at *write time* the file is treated textually so the writer can replace
exactly the generated region and keep user forms intact. Reuse the existing
=read-hactar-lisp= / =write-hactar-lisp= / =merge-hactar-forms= helpers as
reference.

#+begin_src lisp
;;; src/core/generated-file.lisp
(in-package :hactar)

(defmacro generated (&rest body)
  "Load-time: evaluate the generated forms. The first arg may be
   :updated-at <string>, which is ignored at load time."
  (when (eq (first body) :updated-at) (setf body (cddr body)))
  `(progn ,@body))

(defun load-hactar-file (path)
  "Validate, then load .hactar.lisp into a fresh hactar-user environment."
  (let ((forms (read-forms path)))            ; *read-eval* bound to nil inside
    (multiple-value-bind (ok errors) (validate-forms forms)
      (unless ok (error "Invalid .hactar.lisp: ~{~A~^; ~}" errors)))
    (reset-user-registries)
    (let ((*package* (find-package :hactar-user)))
      (dolist (form forms) (eval form)))))

(defun write-hactar-file (path generated-forms)
  "Replace only the (generated ...) region; preserve everything else."
  (let* ((old (when (probe-file path) (uiop:read-file-string path)))
         (user-region (extract-user-region old))   ; everything outside generated
         (block (render-generated-block generated-forms)))
    (atomic-write path                              ; write temp + rename
      (format nil "(in-package :hactar-user)~%~%~A~%~%~A~%" block user-region))))

** Validation (closed surface)

Reuse the schema approach already present (=*hactar-form-schemas*=). The validator
runs on textual forms *before* evaluation.

#+begin_src lisp
;;; src/core/validate.lisp
(in-package :hactar)

(defparameter *surface*
  '(defproject defmodels defroutes
    defhook defmode defagent definterface defcommand defrule
    defskill defprompt defaction deftool defroute defhypertext defdoc
    defsandbox generated))

(defun validate-forms (forms)
  "Return (values ok-p list-of-errors). Every top-level operator must be on
   the surface; generated forms are recursively checked."
  (let ((errors '()))
    (dolist (form forms)
      (cond
        ((not (consp form)) (push (format nil "Not a form: ~S" form) errors))
        ((eq (car form) 'generated)
         (multiple-value-bind (ok errs) (validate-forms (strip-updated-at (cdr form)))
           (declare (ignore ok)) (setf errors (append errs errors))))
        ((not (member (car form) *surface*))
         (push (format nil "~A is not on the Hactar surface" (car form)) errors))))
    (values (null errors) (nreverse errors))))

#+begin_src lisp
;;; src/main.lisp
(in-package :hactar)

(defun main ()
  (let* ((argv (uiop:command-line-arguments))
         (root (find-repo-root)))
    (setf *repo-root* root)
    (unless (probe-file (hactar-file-path root))
      (bootstrap root))
    (load-hactar-file (hactar-file-path root))
    (let ((result (dispatch argv)))
      (format t "~A" (render-result result :text))
      (when *auto-update* (run-hook 'turn.after argv result))
      (uiop:quit (if (eq (result-status result) :error) 1 0)))))

(defun dispatch (argv)
  "Resolve ARGV to an action, agent, tool, or command and run it."
  (let* ((verb (first argv))
         (rest (rest argv))
         (key  (and verb (string-downcase verb))))
    (cond
      ((null verb)                       (run-default-repl))
      ((gethash key *actions*)           (run-action key (args->plist rest)))
      ((gethash key *agents*)            (run-agent  key (format nil "~{~A~^ ~}" rest)))
      ((gethash key *tools*)             (run-tool   key :args (format nil "~{~A~^ ~}" rest)))
      ((gethash key *commands*)          (run-command key rest))
      ((parse-route (format nil "~{~A~^ ~}" argv)) (dispatch-route argv))
      (t (make-result :status :error :message (format nil "Unknown verb: ~A" verb))))))

** Self-update loop with debounce (=src/core/self-update.lisp=)

#+begin_src lisp
;;; src/core/self-update.lisp
(in-package :hactar)

(defstate *auto-update* t "Whether self-update runs after each turn.")
(defvar *last-update-at* 0)
(defvar *update-debounce-seconds* 5)

(add-handler 'turn.after
  (lambda (turn activity)
    (declare (ignore turn))
    (push activity *update-ledger*)
    (when (and *auto-update*
               (> (- (get-universal-time) *last-update-at*) *update-debounce-seconds*))
      (run-self-update))))

(defun run-self-update ()
  "Diffuse edits into the generated region, validate, and reload or roll back."
  (setf *last-update-at* (get-universal-time))
  (let* ((path     (hactar-file-path *repo-root*))
         (backup   (uiop:read-file-string path))
         (current  (current-generated-region path))
         (raw      (diffusion-complete (build-update-prompt current *update-ledger*)))
         (forms    (parse-diffusion-output raw)))    ; reuse existing helper
    (multiple-value-bind (ok errs) (validate-forms forms)
      (cond
        ((not ok) (record-update-failure errs))      ; surfaced via hactar.update.status
        (t (handler-case
               (progn
                 (write-hactar-file path forms)
                 (load-hactar-file path)              ; hot-reload
                 (record-update-success))
             (error (e)
               (atomic-write path backup)            ; roll back
               (record-update-failure (list (princ-to-string e))))))))))
#+end_src

must coexist until cutover without leaving =main= unbuildable.

- Do the rebuild on a dedicated branch; keep =main= shippable throughout.
- Introduce the new systems under new ASDF names (=hactar-core= as the engine)
  while the legacy top-level files remain loadable, so =make build= never breaks
  mid-rebuild.
- Gate the executable's =:depends-on= so the binary can be flipped from the old
  graph to =hactar-core= in a single, revertible commit.
- Old files are only deleted in Phase 10, after the new path passes =make build=
